# الـ State والـ Props والـ Auth — عروض تفاعلية بالعربي

ثلاثة عروض تُشغَّل في المتصفح مثل الشرائح، لكن كل مثال كود فيها هو **React حقيقي يعمل داخل الصفحة**: الطلاب يرون الكود والتطبيق والكونسول جنبًا إلى جنب، ومعها مخططات تدفق ومخططات تسلسل تظهر خطوة بخطوة.

لا يوجد build ولا `npm install`، ولا حاجة للإنترنت (React و Babel محفوظان في `vendor/`). الخط العربي IBM Plex Sans Arabic يُحمَّل من Google Fonts إن توفر الإنترنت، وإلا يُستخدم خط النظام.

```
react-state-auth-ar/
├── index.html      ← صفحة البداية (روابط العروض الثلاثة)
├── state.html      ١ · الـ State: useState، رفع الـ state، Context، Zustand        (34 شريحة)
├── props.html      ٢ · الـ Props وإعادة الرندر: props ضد Context ضد Zustand          (34 شريحة)
├── auth.html       ٣ · الـ Auth في الفرونت إند: التوكنات، التدفق، الكود، الأخطاء      (38 شريحة)
├── shared/
│   ├── css/deck.css      كل التنسيقات (RTL، فاتح/داكن، المخططات)
│   └── js/
│       ├── common.js     تلوين الكود
│       ├── diagrams.js   مخططات التسلسل (.seq)
│       ├── runner.js     تشغيل أمثلة React + create (Zustand مصغّر) + fakeAuthApi
│       └── deck.js       التنقل والخطوات والثيم
└── vendor/          React 18.3.1 + ReactDOM + Babel standalone
```

## التشغيل

افتح `index.html` مباشرة، أو:

```bash
cd react-state-auth-ar
python3 -m http.server 8000     # ثم افتح http://localhost:8000
```

## التحكم

| المفتاح | الوظيفة |
|---|---|
| `←` `Space` `PageDown` | الخطوة التالية ثم الشريحة التالية (الصفحة من اليمين لليسار) |
| `→` `PageUp` | رجوع |
| `O` | كل الشرائح (اضغط للانتقال) |
| `R` | إعادة تشغيل مثال الشريحة من الصفر |
| `T` / `F` | الثيم الفاتح/الداكن / ملء الشاشة |
| `Ctrl/⌘ + Enter` | تشغيل الكود أثناء تعديله |

- أضف `?all` للرابط (مثلًا `props.html?all#13`) لإظهار كل الخطوات مباشرة، وهذا مفيد للمراجعة قبل الكلاس.
- الكتابة داخل مثال لا تحرّك الشرائح.

## ملاحظات للمدرّب

- **`create` في الأمثلة ليس مستوردًا من zustand**، بل نسخة من ~20 سطرًا بنفس الـ API ومبنية على `useSyncExternalStore` (مثل zustand v5 تمامًا). في مشروع حقيقي يكون السطر الأول `import { create } from 'zustand'`. قل هذا للطلاب. شريحة "كيف يعمل Zustand من الداخل" في عرض الـ State تشرح الكود.
- **الـ hooks مستوردة مسبقًا** في الأمثلة (`useState`، `useContext`، `memo`…). في المشروع الحقيقي نكتب `import { useState } from 'react'`.
- **`RenderBox`** صندوق يومض ويعرض "رندر: N" في كل مرة يعيد الكومبوننت الرندر. هو أداة عرض الـ Props كله. كل الصناديق تبدأ بـ 1 (React 18 بدون StrictMode يعمل رندر واحد عند التحميل).
- **الرسالة الدقيقة في عرض الـ Props:** الـ props بحد ذاتها لا تسبّب الرندر. الذي يسبّبه هو رندر الأب. مع الـ props يجب أن يعيش الـ state عاليًا في الشجرة، فكل تحديث يعيد رندر الشجرة تحت الأب كلها. مع Zustand لا يعيد الرندر إلا من اشترك بـ selector تغيّرت نتيجته. أرقام الشريحة 18 (36 رندر مقابل 11 بعد 5 ضغطات) مأخوذة من المثال الحي، فاطلب من الطلاب العدّ بأنفسهم.
- **عرض الـ Auth يطابق مشروع `../react-auth-flow`**: الـ access token في ذاكرة Zustand، والـ refresh token في كوكي httpOnly، والـ interceptor يعمل refresh مرة واحدة فقط (single-flight)، ومعه `AuthBootstrap` والـ route guards. أكواد الشرائح مقتطفات مبسّطة من ملفات المشروع.
- **`fakeAuthApi`** في أمثلة الـ Auth سيرفر وهمي، والـ access token فيه يعيش **10 ثوانٍ** حتى يرى الطلاب انتهاءه والـ refresh أمامهم. الحسابات: `sara@demo.dev` (student) و `omar@demo.dev` (admin)، وكلمة المرور `123456`.
- بعض بيانات الأمثلة بالعربي (مثل البحث في شريحة رفع الـ state)، فقد تحتاج لوحة مفاتيح عربية للكتابة فيها.
