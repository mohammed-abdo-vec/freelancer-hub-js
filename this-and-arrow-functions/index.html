01

What is this?

Every normal function has a hidden variable called this. Its value isn't decided when you write the function. It's decided each time you call it.

An analogy

this works like the word “I”

S“I am hungry.”I = mohammed
O“I am hungry.”I = Omar

Same sentence, different speaker. “I” means whoever is speaking right now.

For a normal function, this = whoever calls it.Not where the function was written. Not where it is stored. Who calls it, at the moment it is called.

The rule

Find the call, then look left of the dot

function speak() {
  console.log(`${this.sound}! I am ${this.petName}`);
}

const cat = { petName: 'Tom', sound: 'Meow', speak };
const dog = { petName: 'Rex', sound: 'Woof', speak };

There is one speak function. The cat and the dog both point to it. this changes because the call changes.

Where the trouble starts

No dot? No owner.

Taking a method out of its object, or giving it to someone else to call, breaks the link.

function speak() {
  console.log(`${this.sound}! I am ${this.petName}`);
}

const cat = { petName: 'Tom', sound: 'Meow', speak };

Wait, which one is it?

A call with no owner: undefined or window?

Modern code · modules, classes, "use strict", Vite, React

this = undefined

Using it crashes right away: TypeError: Cannot read properties of undefined. That's good: the bug is loud and points at the line.

Old classic <script> · “sloppy mode”

this = window

Nothing crashes. You get undefined, NaN and accidental global variables. The bug is silent and shows up far from its cause.

The Run as switch at the top (or M) runs every example both ways. Try it on this one, and on each bug in Part 3.

Choosing this yourself

call, apply, bind: you set this

.call(obj, a, b)

Call now, args separated by Commas

.apply(obj, [a, b])

Apply now, args in an Array

.bind(obj)

Don't call yet. Returns a new function with this locked forever

Rule number four

new makes a brand-new object and calls it this

Today we write class Pet { constructor(…) { … } }. It does the same thing underneath, and it throws a clear error if you forget new.

02

Arrow functions vs normal functions

Arrows look like a shorter way to write a function. But they behave differently, and the biggest difference is this.

Syntax, step by step

Turning a function into an arrow function

Syntax cheat sheet

The shapes of an arrow function

  • No parameters? Use empty ().
  • One parameter? The () are optional.
  • One expression? It is returned automatically.
  • Curly braces { }? It's a normal body, so you must write return.
  • Returning an object? Wrap it in parentheses: ({ … }). (Bug 9 shows why.)

The big difference

An arrow has no this of its own. It borrows the one around it.

Proof

You can't change an arrow's this. Not even with call or bind.

A normal function's this is set by the call, every time it's called.

An arrow's this was fixed when the arrow was created. It uses the this of the code around it, and nothing can change it later.

That is a bug when you want the object (a method). It's exactly what you want inside a method's callback.

BUG 01

The arrow function method

You see: TypeError: Cannot read properties of undefined (reading 'username')Hi, undefined

Why it happens

  1. user.greet() looks right: user is left of the dot.
  2. But greet is an =>, and arrows ignore who calls them.
  3. It borrows this from the code around it. The { } of an object literal is not a function, so “around it” means the top of the file.
  4. At the top of the file, this is undefined (module) or window (script).

Rule: methods are never arrows. Write greet() { }.

BUG 02

The callback inside a method

You see: TypeError: Cannot read properties of undefined (reading 'total')total: 0, and a new global window.total = NaN

Why it happens

  1. cart.sum(), so inside sum, this = cart. ✓
  2. function (price) { } is a new normal function with its own this.
  3. forEach calls it as a plain callback(price). No dot, no owner.
  4. So this.total is undefined.total (crash) or window.total (silent NaN).

Rule: a callback inside a method that needs this? Make it an arrow.

BUG 03

The frozen stopwatch

You see: the number stays at 0, and a new error appears every second.

Why it happens

  1. watch.start(), so inside start, this = the stopwatch. ✓
  2. The function you give to setInterval is not called by your object. The timer calls it.
  3. Timers call it with this = window. So window.seconds becomes NaN and window.display is undefined.

Rule: timers, fetch().then, forEach: if you hand over a callback, it gets someone else's this. Use an arrow.

BUG 04

The Like button that crashes

Run it, then click 👍. You see: TypeError: Cannot set properties of undefined (setting 'textContent')

Live page 0

Why it happens

  1. this.like has no (). You hand over the function; you don't call it.
  2. On click, the browser calls it, with this = the clicked element.
  3. button.counter doesn't exist, so undefined.textContent = … crashes.

Rule: passing this.method anywhere (listeners, timers, React onClick) loses this. Bind it, wrap it, or use an arrow field.

BUG 05

Pulling a method out of its object

You see: the first total works, then TypeError: Cannot read properties of undefined (reading 'itemsreduce')

Why it happens

  1. const { getTotal } = cart copies only the function, not the object it was in.
  2. getTotal() has no dot, so it has no owner.
  3. Passing cart.getTotal to another function is the same thing: whoever calls it later does a plain calc().

Rule: a method only knows its object at the moment you call it with a dot. Copy it out and that's lost.

BUG 06

The arrow that can't find the button

Run it, then click a chip. You see: TypeError: Cannot read properties of undefined (reading 'classListtoggle')

Live page

Why it happens

  1. This is Bug 1 the other way round. Here we want the browser's this (the element).
  2. The browser does pass the element as this, but an arrow ignores it and uses the outer this.
  3. The outer code is the top of the file, so undefined or window.

Rule: in event handlers, prefer event.currentTarget. It works the same in arrows and functions.

BUG 07

The listener that won't go away

Run it, click Ping a few times, click Stop, then click Ping again. It still pings. No error, just wrong.

Live page

Why it happens

  1. Every .bind() call returns a brand-new function.
  2. removeEventListener only removes a listener if you pass the exact same function you added.
  3. So it finds nothing to remove and quietly does nothing. A memory leak waiting to happen.

Rule: bind once and keep the result. Never bind inline if you'll need to remove it.

BUG 08

Arrows aren't full functions

You see: TypeError: Pet is not a constructor, or a sum that comes out wrong

Why it happens

  1. An arrow has no this of its own, so new has nothing to point at the new object. JavaScript refuses: not a constructor.
  2. An arrow also has no arguments of its own. It borrows the outer function's, so it sums checkout(5)'s arguments and gets 5.

Rule: build objects with class. Collect arguments with ...rest. Don't use arguments in new code.

BUG 09

The object that disappears

You see: [undefined, undefined], or a SyntaxError with nothing run at all

Why it happens

  1. Right after =>, a { means “function body starts”, not “object starts”.
  2. Then username: is read as a label (an old, rarely used JS feature). The body runs n and returns nothing, so you get undefined.
  3. With two properties, , role: isn't valid in a body, so you get a SyntaxError.

Rule: to return an object from an arrow without return, wrap it: => ({ … }).

BUG 10

“It worked before I made it an arrow”

You see: ReferenceError: Cannot access 'sayBye' before initialization

Why it happens

  1. A function greet() {} declaration is hoisted: the whole function exists from the first line.
  2. const sayBye = () => {} is a variable. It only gets its value when that line runs.
  3. Change a declaration into an arrow during a “cleanup” and every call above it breaks.

Rule: define arrow functions before you use them. If a helper is called from above, keep it a function declaration.

When you see undefined, NaN or “Cannot read properties of undefined”

The this debugging checklist

  1. Add console.log(this) as the first line of the function. Trust what it prints, not what you expect.
  2. Is the function a function or an =>?
  3. Normal function: find the call, the (). Left of the dot is this. No () where you wrote it? Then someone else calls it (timer, listener, forEach), and they choose this.
  4. Arrow: look outward. What is this in the function around it? An object literal { } doesn't count.
  5. Fix with: method shorthand for methods · arrows for inner callbacks · bind once (or an arrow field) for handlers · event.currentTarget for elements.

Cheat sheet

Normal function

this = decided by the call.

obj.fn() → obj · fn() → undefined/window · fn.call(x) → x · new Fn() → new object · listener → element

Use for: methods, constructors, listeners that need the element.

Arrow =>

this = borrowed from where it's written. Can't be changed.

No new, no own arguments, { after => is a body.

Use for: callbacks inside methods, short helpers (map/filter), class field handlers.

Before you write this, ask: “Who will call this function?”If the answer is “not me, someone else later” (a timer, the browser, forEach, React), that's where the bug lives.
